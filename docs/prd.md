# Product Requirements Document: Prompt Engineering Assistant

**Version:** 1.1
**Date:** April 14, 2025
**Author:** Gemini Assistant (based on user input)

## 1. Introduction

This document describes the requirements for the "Prompt Engineering Assistant," a web application hosted on Deno Deploy. The application's purpose is to assist users in creating effective prompts for Large Language Models (LLMs). This is achieved through three primary functions:
1.  A **step-by-step guide** that helps build prompts based on recognized guidelines.
2.  A **"Talk with the guidelines"** feature where users can ask questions directly about the content of the document "Prompt Engineering_v7 (1).pdf".
3.  An **"Improve my prompt"** feature that automatically suggests improvements to an existing prompt.

The application will utilize the Google Gemini LLM for analysis, answering, and improvement, and will feature a modern, responsive user interface built with Tailwind CSS. All UI text will be managed via an external JSON file to enable localization.

## 2. Goals

* **Improve Prompt Quality:** Help users write clearer, more specific, and effective prompts through guided construction and automatic improvement.
* **Educate Users:** Guide users through best practices for prompt engineering (e.g., specificity, use of examples, instructions over constraints) based on the provided document, via both the guided process and the Q&A function.
* **Streamline Prompt Creation:** Offer both a structured, step-by-step process and a quick improvement feature.
* **Make Guideline Knowledge Accessible:** Make the content of the prompt engineering guide easily accessible via an interactive Q&A interface.
* **Ensure Guideline Adherence:** Actively use the Gemini LLM to validate and improve user prompts against selected key guidelines from the PDF.
* **Deliver Modern UX:** Provide an intuitive, responsive, and aesthetically pleasing user experience using Tailwind CSS.
* **Support Localization:** Prepare the application for future translation by externalizing UI text strings.

## 3. Target Audience

* **Developers:** Integrating LLM functionality into their applications.
* **Content Creators / Copywriters:** Using LLMs to generate text, ideas, etc.
* **Students / Learners:** Seeking to understand and master prompt engineering.
* **All LLM Users:** Wishing to get better and more consistent results from models like Gemini.

## 4. Core Functionality / Requirements

The application will feature tab-based navigation with (at minimum) the following sections: "Build Prompt" (step-by-step), "Talk with Guidelines", "Improve Prompt".

### 4.1 Build Prompt (Step-by-Step User Flow)

* **Functionality:** As described in Version 1.0 (Steps 1-6). Guides the user through building a prompt, focusing on guidelines and Gemini feedback along the way.
    * Step 1: Define Goal & Task
    * Step 2: Draft / Key Elements
    * Step 3: Select Technique (Optional / Recommendation)
    * Step 4: Add Context, Examples, Role (If relevant)
    * Step 5: Guideline Check & Refinement (with Gemini)
    * Step 6: Review & Finalize

### 4.2 Guideline Integration (Gemini LLM in Build Prompt)

* **Functionality:** As described in Version 1.0 (Section 4.2). Gemini analyzes the prompt during construction against key guidelines from the PDF (Simplicity, Specificity, Instructions vs. Constraints, Quality of Examples, Context, Role, CoT Structure).

### 4.3 Talk with the Guidelines (New Feature)

* **Purpose:** Allow users to ask questions in natural language about the content of "Prompt Engineering_v7 (1).pdf".
* **UI:**
    * A dedicated tab/section.
    * A text input field for the user's question.
    * An area to display the answer generated by Gemini.
    * Possibly a history of previously asked questions/answers in the current session.
* **Mechanism (Backend/Logic):**
    * **Data Source:** The content from "Prompt Engineering_v7 (1).pdf" must be made accessible to the LLM.
    * **Recommended Approach (RAG - Retrieval Augmented Generation):**
        1.  Preprocessing: Text from the PDF is extracted, cleaned, and divided into meaningful smaller chunks.
        2.  Embedding: Vector embeddings are generated for each text chunk.
        3.  Storage: Embeddings and corresponding text are stored (e.g., in an in-memory vector database or a simple structure suitable for Deno Deploy).
        4.  Query: When the user asks a question, an embedding is generated for the question.
        5.  Retrieval: The vector database is queried to find the most relevant text chunks from the PDF based on semantic similarity to the question.
        6.  Prompting: A prompt for the Gemini LLM is constructed, containing the user's question and the retrieved relevant text chunks as context.
        7.  Generation: Gemini generates an answer based *solely* on the provided context from the PDF.
    * **Alternative (Simpler, less scalable):** Sending the user's question along with large portions of the PDF text directly to Gemini (limited by context window).
* **Output:** The answer from Gemini should be factually based on the PDF content and presented clearly to the user.

### 4.4 Improve My Prompt (New Feature)

* **Purpose:** Provide users with a quick way to get their existing prompt improved by Gemini based on the guidelines.
* **UI:**
    * A dedicated tab/section.
    * A larger text area (`<textarea>`) where the user can paste their current prompt.
    * A button ("Improve Prompt").
    * An area to display the improved prompt and Gemini's explanation.
* **Mechanism (Backend/Logic):**
    * The user's prompt is sent to the Gemini API.
    * **Meta-Prompt:** The call to Gemini must use a carefully crafted *system prompt* or *instructional prompt* (a "meta-prompt") instructing Gemini to act as a prompt engineering expert. This meta-prompt should:
        * Reference "Prompt Engineering_v7 (1).pdf" as the source of guidelines.
        * Instruct Gemini to analyze the user's prompt for weaknesses regarding the guidelines (clarity, specificity, examples, etc.).
        * Instruct Gemini to *rewrite* the prompt to make it more effective.
        * Instruct Gemini to *explain* the main changes made and justify them by referencing specific principles/guidelines from the PDF.
    * **Output:** The application receives the improved prompt and the explanation from Gemini and displays both to the user.

### 4.5 User Interface (UI) General

* **Technology:** Must be built with Tailwind CSS.
* **Navigation:** Clear and distinct tab-based navigation between "Build Prompt", "Talk with Guidelines", and "Improve Prompt".
* **Design:** Modern, clean, and intuitive design across all sections.
* **Responsiveness:** Must function flawlessly on both desktop and mobile devices.
* **Interactivity:** Dynamic UI updates, clear feedback, and status indicators (especially during API calls).
* **Accessibility:** Should adhere to basic WCAG standards.

### 4.6 Technology Stack

* **Runtime/Hosting:** Deno / Deno Deploy
* **Language:** TypeScript / JavaScript
* **Frontend Framework:** Optional (e.g., Preact, Solid, Svelte, or vanilla JS/TS) - must be compatible with Deno and Tailwind.
* **Styling:** Tailwind CSS
* **LLM Integration:** Google Gemini API
* **Localization:** JSON file(s) for UI text strings.
* **(Potentially for RAG):** Library for PDF parsing, text chunking, vector embeddings (e.g., via ONNX runtime or API calls to an embedding model), vector storage/search.

### 4.7 Deployment

* The application must be easily deployable on Deno Deploy.

### 4.8 Localization

* **Requirement:** All text displayed in the user interface (buttons, labels, titles, instructions, placeholder text, etc.) must be defined in an external JSON file.
* **Structure:** The JSON file should be logically organized with key-value pairs (e.g., `"button.improve": "Improve Prompt"`).
* **Implementation:** The code must retrieve text strings from the JSON file based on keys instead of hardcoding them.
* **Initial Language:** The first version will be implemented with one language file (e.g., English), but the structure must support adding more language files later.

## 5. Design & UX Considerations

* **Clarity Above All:** UI and text must be extremely clear. Clear separation between the different functions (tabs).
* **Intuitive Interaction:** Easy to switch between tabs, input data, and understand output from Gemini in all sections.
* **Visual Feedback:** Loading indicators for API calls. Clear presentation of answers and improved prompts.
* **Context Preservation (Nice-to-have):** Consider if prompts created in "Build Prompt" can be easily sent to "Improve Prompt".
* **Performance:** Fast loading and responsiveness. Efficient handling of potentially large amounts of text from the PDF (RAG).

## 6. Non-Goals / Future Considerations (Version 1.1)

* **Advanced Techniques:** Still does not support complex techniques like Self-consistency, ToT, ReAct, etc., beyond what can be asked about in "Talk with Guidelines".
* **Direct Model Configuration:** No UI for adjusting LLM parameters.
* **Prompt Management:** No functionality to save/organize prompts.
* **User Accounts:** Does not require login.
* **Direct LLM Execution:** The app does not execute prompts to get a final result but focuses on building, analyzing, and improving them.
* **Multi-language UI:** Supports only one language in the initial UI but is prepared for more via the JSON structure.
* **Advanced RAG Tuning:** The first version of RAG might be basic; fine-tuning chunking, embedding models, and retrieval strategy is future optimization.

## 7. Success Metrics

* **User Satisfaction:** High scores on user surveys regarding usability and utility for all three main functions.
* **Task Completion Rate:** High success rate for building, getting answers about, and improving prompts.
* **Feature Usage:** Balanced usage of the different tabs, indicating that all functions meet a need.
* **Perceived Quality Improvement:** Users report being able to create better prompts and better understand the guidelines.
* **Adoption Rate:** Number of unique users and sessions over time.
* **Feedback/Answer Quality:** Gemini's answers in "Talk with Guidelines" are perceived as accurate and relevant. Gemini's improvements/explanations in "Improve Prompt" are perceived as valuable.
